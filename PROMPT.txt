我是齿轮厂热处理车间的工艺员，管着几台可控气氛渗碳炉。每次新零件上线，都要定一条渗碳工艺：几段温度、每段多长、炉气碳势多高，目标是表面含碳量和有效硬化层深落在图纸要求里。以前靠老师傅经验加试炉，试一炉就是十几个小时。我想要一个后端，按工艺曲线模拟碳在钢里的扩散，算出含碳量沿深度的分布，工艺改一改能马上看到硬化层深怎么变。

物理上是一维扩散：零件表层看作半无限厚平板（也允许给定有限厚度、背面不透碳），碳的扩散系数随温度按阿伦尼乌斯关系变化，也允许随含碳量变化。表面边界是炉气向钢表面的传质，通量与炉气碳势和表面含碳量之差成正比，比例系数是传质系数；传质系数取极大时退化为表面浓度等于碳势。工艺曲线由若干段组成，每段给温度、时长、碳势，段与段之间可以有升降温。输出含碳量分布、表面含碳量，以及含碳量降到某阈值（默认 0.35%）处的深度，即有效硬化层深。

可以手算的对照：扩散系数恒为 2e-11 m²/s、表面浓度恒为 1.0%、初始均匀 0.2%，保温 4 小时后含碳量为 0.4% 的深度约 0.873 mm。同一条件下时间变为 4 倍，这个深度应变为 2 倍。质量要守恒：任一时刻钢中碳的增量，等于从开始到此刻穿过表面的通量积分，服务要把这两者的相对差随结果报出来。

数值方法由你选择，但有几处要你想清楚并写进文档：时间推进用什么格式、在工艺切换（碳势或温度突变）附近会不会出现振荡或负浓度，出现了怎么处理；网格是均匀还是在表面加密，步长怎么随温度段调整。服务要能做收敛核查：同一工艺在网格和时间步各加密一倍后，硬化层深的变化量要随结果给出，超过你设定的阈值时提示结果不可靠。

计算以作业形式运行，因为长工艺加细网格可能要算一阵子。作业可以查进度（已模拟到工艺的第几段、第几分钟）、可以取消；服务重启后作业从最近的检查点继续，最终分布与一口气算完完全一致。工艺作为有版本的配方保存，每个配方版本关联它的模拟结果；我在某一段上改了时长，只需要从改动那一段开始重算，前面各段的结果直接复用，但复用后的结果必须与整条工艺从头算的一致。两个配方版本的分布曲线和硬化层深可以对比。

这些输入要拒绝并指出字段：温度不在 800 到 1100 °C 之间、段时长非正、碳势不在 0 到 1.6% 之间、初始含碳量不小于碳势、传质系数为负、有限厚度非正、阈值不在初始含碳量与碳势之间。

测试要包含恒定扩散系数的解析对照、时间四倍深度两倍、质量守恒误差、网格加密收敛核查、从中间段起的增量重算与全量一致、检查点续算一致、突变工艺下不出现负浓度。

用 Python 3.12 和 FastAPI 实现，配方版本、作业、检查点与结果存 PostgreSQL 16，数值部分可以用 NumPy、SciPy。物性与扩散系数、边界传质、数值求解、收敛核查、配方版本与增量重算、作业与检查点、接口请分别放在不同模块。镜像从 python:3.12-slim 构建，数据库那个容器用 postgres:16-alpine，两个容器交给 docker compose 管，pytest 测试放在仓库里。对外只有 HTTP 接口。
